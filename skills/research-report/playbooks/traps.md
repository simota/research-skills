# Traps — report

- **The summary is what gets quoted.** It will be read alone, forwarded, and pasted into a
  decision doc without its conditions. Write it so that being read alone is safe.
- **Readability edits are where hedges die.** "May reduce latency under tuned configurations"
  becomes "reduces latency" in the tightening pass. Shorten by removing claims, not qualifiers.
- **Ranges get rounded into points.** A single number is easier to read and is a different claim.
  Keep the range, or state the point estimate *with* the range.
- **Examples invented for clarity read as evidence.** Any illustration not in the ledger is
  labelled as hypothetical or is cut.
- **"Research shows" is a citation-shaped hole.** Name the source inline; a claim whose support is
  a genre is unsupported.
- **Confidence labels get sanded off in the second draft.** Verify labels survive editing — this
  is a required check in `VERIFY`, not a matter of care.
- **A well-formatted report reads as more certain than a rough one.** Polish inflates perceived
  confidence, so state uncertainty more explicitly the more finished the document looks.
